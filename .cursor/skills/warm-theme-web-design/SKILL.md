# 温馨主题网页设计规范

本规则仅用于 UI 视觉设计任务（配色、字体、间距、布局、移动端响应、反模式）。**与业务逻辑、后端、API、数据处理无关，不适用于这些工作。** 当对话涉及视觉设计时，Cursor 据此直接编写、修改代码；视觉规范由规则说了算，不得擅自改动主题或自行发挥配色/字体。

## 设计主张（Impeccable 核心）
- 打磨"完整、有品位、克制"的设计，不堆装饰。
- **改进（refine）保留既有身份**：细化、收紧，不推翻已有视觉世界。
- **每页只做一个"作者时刻"**：一个主视觉焦点，其余区块安静退后。
- **验证要有界**：一次性批量检查，不陷入无休止自审。

## 风格设定
- **整体气质**：简约、温暖、治愈、克制；低饱和暖色，干净留白，无花哨装饰。
- **作者时刻**：温暖圆体标题 + 柔陶土橙点缀，一眼"温馨治愈"，其余全部退后。

## 反模式黑名单（必须规避，用户钉死主题可豁免，其余一律禁止）
- ❌ 同尺寸"图标+标题+文字"卡片平铺成整页骨架（卡片是偷懒容器，嵌套卡片永远错）
- ❌ 大数字+小标签+统计+强调色的"hero指标"模板
- ❌ 每个区块都加眉题/小标签（heading 自己撑得起，删掉眉题）
- ❌ 区块编号 01/02/03（除非序号本身传达信息）
- ❌ 纯装饰用渐变文字、毛玻璃/模糊（除非是具体效果）
- ❌ 卡片/列表上超过 1px 的彩色左边框
- ❌ 硬偏移阴影 `box-shadow: 4px 4px 0`（新粗野主义戏服）
- ❌ 用 emoji/Unicode 符号冒充图标系统（图标统一风格绘制）
- ❌ 用系统 display 字体（Impact/Arial Black）当主视觉字体（要自托管有性格的字体）
- ❌ 等宽字体当"科技感"戏服（只有真代码/数据/度量才用）
- ❌ 密密麻麻大段文字、多层卡片嵌套堆砌、大量渐变、冗余装饰、夸张色彩对比、繁杂动效

## 移动端强制约束（mobile-first，整合 ui-mobile 专项）
**以下为不可协商标准，每个 UI 元素必须通过检查：**
1. **触摸目标（关键）**：所有可交互元素（按钮/链接/图标按钮/列表行）≥44×44px；图标按钮 44×44 正方形；避免 `height:30`、`padding:4` 过小硬编码。列表行 minHeight 44，padding 12/16。
2. **可见边界（关键）**：每个按钮必须有可见边界——主按钮实底+对比文字；次按钮可见底色；幽灵按钮 ≥1px 边框；**禁止**透明无边框隐形按钮、文字色=背景色。
3. **颜色对比度**：正文/占位文字 ≥4.5:1，大文字 ≥3:1；文本低于 4.5:1 禁止。
4. **无障碍标签**：每个可交互元素有可访问标签；纯图标按钮（无可见文字）必须有 label；相关元素按语义分组。
5. **按压/聚焦状态**：每个可交互元素有可见按压反馈（opacity/色变）；键盘 focus ring 可见。
6. **安全区**：顶部/底部适配刘海与动态岛（用安全区，不写死 `paddingTop:44`）。
7. **字号下限**：文本 ≥12px，正文 17px 起，标题可达 34px；input ≥16px（防 iOS 缩放）；避免固定高度破坏大字。
8. **不依赖 hover**（移动端无 hover）；主操作按钮置于屏幕下半区拇指热区，支持单手。
9. **响应式是结构性动作**：桌面多列转单列；导航降级为底部操作栏/抽屉；按重要性重排/折叠/回流/揭示，不缩小字号硬塞。
10. **间距**：4/8/16/24/32 网格；相关元素 8，区块 32。
11. **动画**：200–300ms，GPU/原生驱动保持 60fps；仅细微按压反馈，禁止花哨动效。
12. **图标**：统一线条/描边风格，禁止 emoji/Unicode 冒充图标。

### iOS / Android 差异（做原生或 PWA 时参考）
- iOS（HIG）：扁平+微妙深度、SF Symbols、大标题 34pt、圆角 10–14pt、阴影 shadowColor+offset+opacity。
- Android（Material 3）：动态取色、实心/描边图标、标题 22pt、圆角 12–28pt、阴影用 elevation。

## 排版与字体规则
- **标题字体**：温暖可爱圆体，圆润、柔和、有亲和力。中文字体：站酷快乐体 / 圆体（MiSans Rounded、OPPO Sans 圆润变体）；西文字体：Fredoka、Baloo 2、Comic Neue、ZCOOL KuaiLe。标题圆角感、字距略宽。**自托管字体，不退回系统字体**。
- **正文字体**：干净、易读、行高宽松的无衬线字体，文字精简，保证小屏阅读舒适。
- **层级**：大标题圆润醒目、正文清爽、辅助信息轻量浅灰；字号/字重要有明显台阶，标题字距下限 -0.04em 以内。
- **正文行宽**：65–75 字符，display 最大 6rem。

## 配色系统（暖色调简约）
- 背景：米白 / 极浅暖米色（`#FFF8F0`、`#FDF6EE`）。
- 主色：柔和浅陶土暖橙（`#E8A87C`、`#F0B27A`）或浅杏色。
- 点缀/辅助：浅奶茶、淡杏、奶油色，用于按钮/高亮/分隔。
- 文字：主文字深炭灰（避免纯黑，`#3A3A38`）；次要文字浅灰（`#9C9C96`）。
- 阴影：极低透明度软阴影、新拟态轻柔和质感；**禁止**厚重深色阴影、硬偏移阴影。
- **对比度**：正文与占位文字 ≥4.5:1，大号文字 ≥3:1；彩色面上不要用灰色做次要文字，改用该色相浅色或前景色。

## 项目硬约束与阅读舒适（手机端页面必读）
本项目为**手机端使用的移动端网页**（物品管理、表单、列表、登录），面向中青年用户，以下是不可违反边界与阅读舒适要求：

### 硬约束（只动视觉，绝不越界）
- **只改视觉层**（配色、字体、间距、布局、交互反馈、动效）。
- **禁止改动**：业务逻辑、路由/页面流程、数据字段、CloudBase 对接、接口调用、状态管理、数据结构。视觉调整不得要求或暗示重构这些部分。
- 以现有 DOM 结构和组件为准，不新增/删除功能。

### 目标设备
- **手机优先**：适配安全区、底部操作栏、拇指热区；375–390px 窄屏为基准。

### 阅读舒适（字号别太小即可）
- **字号不小**：正文建议 ≥16px，按钮文字 ≥16px，辅助信息 ≥13px；标题层级清晰。
- **点击区域舒适**：交互元素 ≥44×44px；按钮内边距适中，不局促。
- **对比清晰**：主文字与背景对比明确，暖色主题下文字易读。
- **减少误触**：主操作按钮有清晰视觉层次，避免过小图标/链接。

### 布局原则（已知问题规避）
- **底部留固定安全区**：底部操作栏避开系统手势区，预留足够 padding。
- **悬浮控件避开主按钮**：任何悬浮/常驻控件（如音乐播放控件）**不得遮挡**「保存 / 删除 / 主操作」按钮；需为其预留专用位置或自动让位。
- **主操作可达**：保存、删除、登录等关键按钮始终在拇指可及范围且不被覆盖。

## 布局原则（Impeccable）
- **按含义分组**：先靠接近性（间距）聚组，再加容器或装饰；不用容器弥补弱分组。
- **节奏来自对比**：紧凑与宽松间隔的刻意对比制造节奏，不是同一间距值重复到所有东西一样重。
- **用文档化间距刻度**：4 单位基数（4/8/16/24）。
- **层级跟随产品优先级**，不是框架默认。
- **眯眼测试（squint test）**：模糊细节后，主元素、次元素、大分组按顺序一眼可见。
- **密度匹配使用频率**：高频操作给足空间，低频辅助信息压缩。

## Tailwind 建议
- 将上方 token 固化为 `tailwind.config` 的自定义主题（colors / borderRadius / spacing / fontFamily / boxShadow），页面用语义化类名引用，避免散落魔法数值。
- 圆角：大卡片 16px，按钮/capsule 20px，小元素 8px；卡片不超过 16px。
- 阴影统一软质感：`0 4px 12px rgba(0,0,0,0.06)`，禁止硬偏移。

## 组件规范要点
- **按钮**：主按钮陶土橙底 + 白字 + 圆角 20px，按下轻微缩放（scale 0.98）；触摸目标 ≥44px。
- **输入框**：高 ≥48px，内边距 16px，字号 16px，圆角 12px，浅暖底 + 浅边框，focus 用陶土橙描边。
- **卡片**：整宽 16px 圆角白暖卡，软阴影；图标统一线条风格，不嵌套卡片。
- **导航**：移动端底部操作栏（含安全区留白）或抽屉；不依赖 hover。

## 状态要求
每个可交互组件都要覆盖：hover、按下/active、禁用、加载、错误、空态；真实内容、可用控件、键盘焦点（focus ring 陶土橙描边）。

## 开发交付要求
- 所有样式严格遵循本规范 token，**视觉改动必须先说明再执行，不擅自改风格**。
- **只动视觉**：绝不改动业务逻辑、路由、数据字段、CloudBase 对接。
- 写完后自查：对比度、间距节奏、字号台阶、状态齐全、移动端单列回流无溢出、无反模式。
- **验收标准**：在窄屏（约 390px 宽）上，表单、列表、登录页面都能完整滚动并点到「保存」等主操作；主操作不被任何悬浮控件遮挡。
